## 2. IDENTITY

| ID | Where generated | Type | DB- or app-generated | Uniqueness scope | Reused across systems? |
|---|---|---|---|---|---|
| **user ID** | Supabase Auth on sign-up | uuid | Supabase | global (`auth.users`) | **Yes** — same login for customer app, Partner app, rider, Master (D1). Written to `ol_orders.user_id`, `org_users.user_id`, `riders.user_id`, `platform_admins.user_id` |
| **organization ID** | OS (outside repo) | uuid | DB default in OS | global | **Yes** — `ol_orders.organization_id`, `ol_stores.organization_id`, POS `orders.organization_id` |
| **location ID** | OS `locations.id` | uuid | OS | global | Only as `ol_stores.location_id` (0028 DRAFT). Customer "location" is a different thing: `city_id text` (`'latur'`) plus the delivery address lat/lng |
| **city ID** | `ol_service_areas.city_id` | text slug `latur` | manual | global | Every `city_id` column; HTTP `?city=` / `x-city` header (`catalog.ts resolveCity`) |
| **device ID** | `frontend/src/api.ts randomId(24)` → 48 hex chars, saved at AsyncStorage key `onecity.customer-key.v1`, sent as header `x-customer-key`. Server regex: `^[A-Za-z0-9_-]{24,128}$` | string | app-generated (client) | per phone install; new key after "Clear this phone" | Not sent to other systems; only its SHA-256 is stored (as `customer_hash`) |
